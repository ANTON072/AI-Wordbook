MCPとは何か

MCP（Model Context Protocol）は、Anthropicが2024年11月に公開したオープン規格です。 AIアシスタント（Claude）が外部のツールやデータソースと会話できるようにするための「共通言語」を定義します。

一言で言うと： ClaudeにUSBポートを追加するようなもの。どんな周辺機器（ツール）でも、MCPという規格に対応していれば、Claudeが自動的に使えるようになります。

MCPが解決する問題を理解するため、MCPがなかった場合を考えてみます。

😫

MCPなし（従来）

ツールごとに専用の連携コードを書く必要がある。GitHub用、Slack用、DB用、それぞれバラバラな実装が必要。

✨

MCPあり（現在）

MCP規格に沿ったサーバーを1つ書けば、Claudeを含めあらゆるAIクライアントから使えるようになる。

図1 — MCPの立ち位置：ClaudeとMCPサーバー群の関係
2

全体アーキテクチャ

MCPは ホスト・クライアント・サーバー の3層で構成されます。

🏠

ホスト (Host)

Claude Desktopや本プロジェクトのようなアプリ全体のこと。複数のMCPクライアントを管理し、ユーザーとの対話を担当する。

🔌

クライアント (Client)

各サーバーへの接続を1本ずつ管理する役割。Claude本体の中に組み込まれており、1サーバー = 1クライアント接続。

⚙️

サーバー (Server)

実際にツールやデータを提供する側。ファイル操作、DB検索など具体的な機能をここに実装する。

図2 — MCP 3層アーキテクチャ：ホスト内のクライアントが各サーバーと1対1で通信する
3

トランスポート層

「トランスポート」とはメッセージの運び方のことです。手紙を届けるとき、郵便・宅配便・手渡しなど方法が複数あるのと同じように、 MCPにも複数のトランスポート方式があります。データの中身（JSON-RPC）は同じでも、届ける手段が異なります。

図3 — 2種類のトランスポート：stdio（プロセス間）vs Streamable HTTP（ネットワーク）

本プロジェクトでのトランスポート選択

AI-Wordbook ではリモート HTTP トランスポートを採用。 MCPサーバーは Next.js の Route Handler（src/app/api/mcp/route.ts）として実装され、 AWS Lambda 上で動作します。Claude Desktop は HTTPS で直接クラウドのエンドポイントへ接続します。

ローカルにプロセスを立てる必要はありません。認証には OAuth 2.0 PKCE（Cognito） を使い、 Claude Desktop が自動的にアクセストークンを取得して Bearer ヘッダーに付与します。

比較項目stdioHTTP + SSE
通信経路標準入出力（プロセス間）HTTP/HTTPS（ネットワーク）
サーバーの場所同一マシン必須リモートも可
認証不要（OS権限で制御）Bearer Token等が必要
セットアップ簡単やや複雑
主な用途ローカルツール、開発環境SaaS連携、チーム共有
4

プロトコル仕様 — JSON-RPC 2.0

MCPのメッセージはすべて JSON-RPC 2.0 形式で送受信されます。 JSON-RPCとは「JSONを使った関数呼び出しの規格」です。 HTTP APIのように「このURLにPOST」ではなく、「このメソッド名で呼び出し」という形式です。

メッセージの3種類

📤

Request（リクエスト）

呼び出し側が送る。idで識別し、対応するResponseを待つ。

📥

Response（レスポンス）

呼ばれた側が返す。同じidで対応するRequestと紐づく。

📢

Notification（通知）

idなし。返答不要の一方向メッセージ。イベント通知等に使う。

実際のJSONメッセージ例

// ① Claudeが「ツール一覧を教えて」とサーバーに送るRequest
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {}
}
// ② サーバーが「こんなツールがあります」と返すResponse
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [
      {
        "name": "register_word",
        "description": "英単語を単語帳に登録する",
        "inputSchema": {
          "type": "object",
          "properties": {
            "word":    { "type": "string", "description": "英単語" },
            "entries": {
              "type": "array",
              "description": "辞書エントリ（品詞・和訳・例文）の配列",
              "items": {
                "type": "object",
                "properties": {
                  "partOfSpeech": { "type": "string" },
                  "translation":  { "type": "string" },
                  "examples":     { "type": "array", "items": { "type": "object" } }
                }
              }
            }
          },
          "required": ["word", "entries"]
        }
      }
    ]
  }
}
// ③ Claudeが「このツールを実行して」と送るRequest
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "register_word",
    "arguments": {
      "word": "ephemeral",
      "entries": [
        {
          "partOfSpeech": "adjective",
          "translation": "短命な、一時的な",
          "examples": [
            { "en": "Fame is ephemeral.", "ja": "名声は束の間のものだ。" }
          ]
        }
      ]
    }
  }
}
5

MCPの3つの機能（Capability）

MCPサーバーが提供できる機能は3種類に分類されます。

図4 — MCPの3つのCapability：Tools / Resources / Prompts

本プロジェクトのスコープ： AI-Wordbookでは主に Tools（単語の追加・取得・削除・検索）を実装します。 ResourcesとPromptsは将来の拡張候補です。

6

接続ライフサイクル

ClaudeがMCPサーバーと接続を確立してから終了するまでの流れを「ライフサイクル」と呼びます。 毎回3つのフェーズを経て通信が行われます。

図5 — MCPの接続ライフサイクル：Initialize → Operation → Shutdown

各フェーズの詳細

  1. 初期化（Initialize）

    Claudeからサーバーへ「MCPバージョン」「自分のCapability」を伝える。サーバーは「自分が対応しているバージョン」「提供できるCapability一覧」を返す。これをハンドシェイクと呼ぶ。

  2. 通常操作（Operation）

    ハンドシェイク完了後、Claudeはツール一覧を取得し、ユーザーの指示に応じて必要なツールを呼び出す。このやり取りが会話中に何度も行われる。

  3. 終了（Shutdown）

    Claude Desktopが終了する、またはセッションが切れると接続をクローズ。stdioの場合、子プロセスも終了する。

7

サーバーを実装する

MCPサーバーの実装には公式SDKを使うのが最短です。 Python・TypeScript・Javaなど複数言語が提供されています。

TypeScript SDK の例（本プロジェクト想定）

Next.js の Route Handler に McpServer をマウントする形で実装します。

// src/app/api/mcp/route.ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StreamableHTTPServerTransport } from "@modelcontextprotocol/sdk/server/streamableHttp.js";
import { z } from "zod";

const server = new McpServer({
  name: "ai-wordbook",
  version: "1.0.0",
});

// ツールを登録（単語登録）
server.tool(
  "register_word",
  "英単語を単語帳に登録する",
  {
    word:    z.string().describe("登録する英単語"),
    entries: z.array(z.object({
      partOfSpeech: z.string().describe("品詞"),
      translation:  z.string().describe("和訳（1〜200文字）"),
      examples:     z.array(z.object({
        en: z.string(),
        ja: z.string(),
      })).describe("例文ペア（1〜3件）"),
    })).describe("辞書エントリの配列"),
  },
  async ({ word, entries }) => {
    const url = await saveWordToDB({ word, entries });
    return {
      content: [{ type: "text", text: url }],
    };
  }
);

// Next.js Route Handler として POST を受け付ける
export async function POST(req: Request) {
  const transport = new StreamableHTTPServerTransport({ sessionIdGenerator: undefined });
  await server.connect(transport);
  return transport.handleRequest(req);
}

Claude Desktop への登録

ローカルプロセスを起動するのではなく、デプロイ済みの URL を指定するだけです。

// ~/Library/Application Support/Claude/claude_desktop_config.json
{
  "mcpServers": {
    "ai-wordbook": {
      "url": "https://yourdomain.com/api/mcp"
    }
  }
}

登録後の流れ： Claude Desktop が起動すると URL に接続し、OAuth 2.0 PKCE フローを自動で開始します。 ブラウザで Cognito の認証画面が開き、ログインするとアクセストークンが発行されます。 以降はアクセストークンを Bearer で付与して /api/mcp を呼び出し、会話中にツールを使えるようになります。

8

セキュリティ設計

MCPサーバーはClaudeから直接呼び出されるため、セキュリティ設計が重要です。主な注意点を整理します。

リスク対策本プロジェクトの実装
不正なツール呼び出し 入力バリデーション（zodスキーマ） 実装済 zodで型・範囲を検証
権限昇格 最小権限の原則。DynamoDB読み書きのみ許可 実装済 IAMロールでスコープ限定
プロンプトインジェクション ツールの説明文にインジェクション用語を含めない 要注意 descriptionを安全に保つ
認証情報の漏洩 envで注入。コードにシークレットを埋め込まない 実装済 環境変数経由で渡す
意図しないデータ削除 破壊的操作は確認ステップを追加 検討中 softDelete方式

プロンプトインジェクションに注意： ツールのdescriptionやnameフィールドに悪意ある指示を埋め込まれると、 Claudeが想定外の動作をする可能性があります。 MCPサーバーのソースコードを常に自分でレビューし、信頼できるソースのみ使用してください。
