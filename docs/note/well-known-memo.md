# `.well-known/` とは

## 概要

RFC 8615 で標準化された「既知のURL」を置くための特殊なディレクトリ。
`/.well-known/` 以下のパスは、サーバーが自分自身に関するメタ情報を公開する場所として予約されている。

## MCPサーバーで必要になる理由

通常のWebアプリ認証では、Auth0・Cognito・Google等の**既存認証サービスをクライアントとして使う**立場なので、`.well-known/` を自分で作る必要はない。それらのサービスが公開してくれている。

MCPサーバーでは **自分自身がOAuthサーバー（認可サーバー）の役割を担う**側になる。
Claude Desktopは「OAuthクライアント」として `.well-known/` を読みにくるため、自分のサーバーがそれに応答できなければならない。

## コールバックURLとの違い

- **`.well-known/`** — 「認証サーバーがどこにあるか」をクライアントが事前発見するためのもの
- **コールバックURL（redirect_uri）** — 認証完了後にユーザーを戻す先を指定するもの

OAuth 2.0の流れ：

```
1. クライアントが .well-known/ を読む（認証エンドポイントのURLを発見）
2. ユーザーを認証サーバーへリダイレクト
3. 認証サーバーがコールバックURL（redirect_uri）へリダイレクト
4. クライアントがコードを受け取りトークンと交換
```

`.well-known/` はステップ1を省力化するもので、コールバックURLとは別の関心事。
