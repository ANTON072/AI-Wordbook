# ユビキタス言語定義（共通言語）

## 概要

### PRD・機能設計書・技術仕様書・リポジトリ構造定義書・開発ガイドラインとの対応関係

本書は 001〜005 に登場する用語の表記ゆれを解消し、各概念の正の表記・定義・コード識別子との対応を1つに定める。ドメイン用語・UI 用語・コード命名語彙の単一情報源（SSOT）であり、他ドキュメントとコードはこの表記を正として参照する。

用語が指す概念の仕様（正規化ルール・JWT 検証項目・URL 形式・キー設計など）は上位ドキュメントが正であり、本書では復唱しない。必要な箇所は出典番号で指す。

### 用語定義スコープ

- 対象：ドメイン用語・UI 用語・コード命名語彙の「正の表記」と、対応するコード識別子・別名／禁止表記
- 対象外（001〜005 が既定）：各用語が指す概念の実装詳細・システム構成・ビジネスルール。技術・ライブラリの選定は 003、物理配置は 004、コードの書き方は 005、論理設計は 002 が正
- 収録範囲：表記がゆれている概念、またはこのアプリ固有の命名対象に絞る。AWS サービス名やフレームワークの公式用語など、表記が一意で公式ドキュメントから意味を回復できるものは収録しない

## 確定事項と根拠

| 決定 | 根拠 |
|----|----|
| 実装識別子と一致する表記を正とする | コードと文書で語が食い違うのを防ぐ。例：「正規化済み単語」は SK 属性 `word`、「ユーザー識別子」は PK 属性 `userId` に揃える |
| 概念の粒度で語を分ける | 「辞書情報（`entries`＝配列）」「品詞エントリ（`Entry`＝配列の1要素）」「単語データ（レコード全体）」を別語にし、粒度の取り違えを防ぐ |
| 不正確な語を是正する | 「同綴異義語」は book の名詞／動詞のような複数品詞の語には不正確なため、「複数品詞」を正とする |
| 略記より正式名を優先する | MCP ツールは register/delete/update/search の略記でなく `register_word` 等の正式名で表記し、コードと一致させる |
